# Application review against the BRD — 2026-11-06

Scope: everything built through the gap-closure step (Identity, Audit, Administration, HR basic, Patient,
Appointment and queue, Clinical OPD and inpatient, Billing, IPD, Nursing, Notifications, dashboard),
checked against docs/BRD.md, docs/SRS.md and the decisions in docs/OPEN-QUESTIONS.md. Five parallel
read-only reviews, one per phase plus cross-cutting concerns; every finding below was verified in code.

Status column: **Fixed** = corrected in this step (see CHANGELOG 2026-11-06); **Deferred** = a feature or
design change that needs its own approved step; **Accepted** = deliberate decision, left as is.

## 1. Defects found and their status

### Billing
| # | Finding | Status |
|---|---|---|
| B1 | A final IPD bill whose charges are all zero-priced could not be finalized, so discharge was blocked | Fixed |
| B2 | Charges posted after the final bill was prepared (e.g. a late ward-round fee) were logged and lost | Fixed: a supplementary running bill is opened for the stay |
| B3 | Cancelling a partly paid OPD appointment left a due with nobody told to refund | Fixed: cashiers with refund rights are notified |
| B4 | Cancelled invoice displayed payment status "Paid" | Fixed |
| B5 | One person could request, approve and pay out the same refund | Fixed: approver ≠ requester, payer ≠ approver |
| B6 | Invoice lines had no database immutability trigger, unlike the other financial tables | Fixed |
| B7 | Outstanding balance excludes draft running bills | Accepted (running bills are settled at discharge; shown on the account as "running") |
| B8 | An approved discount can be refused if a payment lands in between; it must be rejected and re-requested | Accepted |

### Appointment and OPD
| # | Finding | Status |
|---|---|---|
| A1 | An InConsultation appointment from a previous day locked the doctor out of their queue with no recovery | Fixed: stale ones auto-close when the doctor next opens the queue; the in-progress check is per day |
| A2 | A charting doctor could not release a patient called in by mistake without entering a diagnosis | Fixed: "Close without consultation" in My Queue |
| A3 | Two simultaneous "Call next" clicks could put two patients in consultation; the second vanished from the screen | Fixed: database unique guard |
| A4 | Rescheduling within the same full session was refused | Fixed |
| A5 | Same patient, same doctor, same day in two sessions could double-book under concurrency | Fixed: lock per doctor-day |
| A6 | Queue display board omitted the completed count the BRD lists | Fixed |
| A7 | Anyone with the vitals permission could void any patient's vitals | Fixed: author-only, like other records |
| A8 | Doctor session overlap check could race | Fixed |
| A9 | UI "today" came from the workstation clock, server uses Asia/Dhaka | Fixed |

| P3 | Patient documents (lab reports, discharge summaries) were auto-granted to the Super Administrator and downloads were not audited | Fixed |

### Platform and operations
| # | Finding | Status |
|---|---|---|
| X1 | Refresh cookie was always Secure, so over plain HTTP on any non-localhost host every session died after 15 minutes | Fixed: follows the request scheme; TLS at the proxy documented as required for production |
| X2 | Refresh and logout endpoints had no rate limit | Fixed |
| X3 | API port published to the network with forwarded headers trusted from anyone (spoofable rate-limit key and login IP) | Fixed: API bound to localhost, forwarded headers trusted only when configured |
